# Scaffold React Native

1. Default to Expo with TypeScript. Validate the app name and reverse-domain organization before invoking any command. From the target root run `npx create-expo-app@latest react-native-app --template default --yes --no-agents-md` after confirming the installed CLI options. If an older CLI lacks --no-agents-md, use its supported options and do not activate any generated integrations. Set the display name and Expo slug from the chosen name in app config, and set ios.bundleIdentifier and android.package to the validated identifier. Preserve the template’s SDK and lockfile.
2. With --bare, use `npx @react-native-community/cli@latest init <AppName> --directory react-native-app`. Inspect init --help and use the supported `--package-name <identifier>` and `--skip-git-init` options where available. Keep template Android and iOS settings consistent with the chosen ID, including applicationId, bundle identifier and any identifiers derived from them. Never require CocoaPods on a non-macOS host.
3. Inspect the generated entry point before editing. Add a Home screen with seedable state and an accessible action, with Expo Router route files kept separate from reusable components. Add theme tokens in the chosen structure. Add typed local message tables with a complete English fallback and the selected locales. Use the project's locale and RTL mechanism, or add an approved locale mechanism using Expo's compatible dependency resolver for SDK modules. Keep the app’s main entry wired to Home.
4. Run the build reference’s applicable Checks. Report the hosts actually built, any missing tooling, and whether RTL was exercised. Append the standard Sauces scaffold README section with run commands. Record and rescan only after the template and overlay exist.
